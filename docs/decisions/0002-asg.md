# 0002 — Appliance: the EC2 machinery of an appliance, and how it is adopted

> Carried over from truvity/aws-structure (its ADR 0004) when the code moved to this repository in v0.1.0. `pkg/bootstrap` is now `bootstrap`, `pkg/appliance` is now the root package `asg`, and decision numbers below are the old ones.

**Status:** Accepted

## Context

Two estates run appliances: the status box (an Auto Scaling group of one with
a warm pool, in `truvity/observability`) and the Tailscale routers (groups of
one to several, in `truvity/tailscale`). Each wrote its own group, launch
template, role, security group, lifecycle hook and S3 uploads, and each role
policy was written by hand. `pkg/bootstrap` (decision 0003, here 0001) already composes
the user-data and reports, per boot, to the lifecycle hook. What remains is
the AWS side.

## Decision

1. **Where.** `pkg/appliance`, in this repository (it is the AWS organisation
   library; VPCs live elsewhere). It imports `pkg/bootstrap`; `pkg/bootstrap`
   stays free of Pulumi and AWS.
2. **Every building block is optional or configurable.** Group size, warm
   pool, hook (inline on the group, or a resource), security group rules
   (inline, `aws.vpc.*Rule` or the legacy `aws.ec2.SecurityGroupRule`), image
   (id, name filter or SSM parameter) and alarms.
3. **The hook abandons by default.** `bootstrap-ready.service` sends CONTINUE
   on every boot; a missed one must replace the instance rather than put a
   half configured one in service. `CONTINUE` as the default result needs an
   explicit `UnsafeDefaultContinue`. A warm pool without a hook is refused:
   the instance would be stopped before its first boot finished.
4. **The role is built from the user-data.** `ssm:GetParameter` on exactly the
   plan's parameters, `s3:GetObject` on exactly the plan's object keys, the
   two autoscaling actions on the group, then the caller's statements. No
   managed policy by default (`AmazonSSMManagedInstanceCore` reads every
   parameter of the account). Policy builders are exported and return exact,
   byte-stable JSON, so a golden is a review artifact. A bare `*` action is
   refused.
5. **The library uploads the plan's objects** (bootstrap leaves that to the
   caller) and makes the launch template and group depend on them.
6. **IMDSv2 is always required.** The hop limit is configurable (default 1).
7. **Adoption is two steps and both are possible.**
   - Step A: the old user-data goes through `bootstrap.Verbatim`, the old
     policy through `IAM.Policy`, and `Compat` keeps the component type
     (`ComponentType`, or `Flat` for a program that had no component),
     logical names (`Compat.Names`), aliases (`Compat.Aliases`) and physical
     names (`Names`). The preview is empty. The status box is the proof:
     `statusbox_test.go` compares the resource set with one recorded from
     its module.
   - Step B: composed user-data and no `IAM.Policy`. One launch template
     version, an instance refresh, an in-place policy update.
8. **Extension points are data.** A `Module` returns a `Contribution`
   (fragments, statements, parameters, object keys, ingress rules, managed
   policies). It creates no resource, so a module cannot change the logical
   names of the appliance. No module ships here; sshd user certificates,
   self-registering DNS, journald and swap follow in a later change.
9. **Names are resolvable before the plan is rendered.** The plan needs the
   group and hook names for its lifecycle; `Names.Resolve(name).Lifecycle()`
   gives them without creating anything.

## Roads not taken

- Taking a `*bootstrap.Plan` instead of `*bootstrap.Rendered`: would rule out
  `Verbatim`, the step-A path.
- Generating the whole policy with no override: step A would then tighten the
  role and the preview would not be empty. The tightening belongs to step B.
- A hook always inline: the router declares a separate one; both are kept.
- Modules that create resources: would put their names in the appliance's
  state and make adding one a migration.
- Defaulting to no hook: forgetting it removes the only guard against a
  half configured instance. The hook is a pointer so that "none" is a choice,
  and the documentation says to set it.

## Consequences

Additive. The status box and the routers can adopt the package one
environment at a time; the first apply after step A shows nothing, the first
after step B shows the launch template and the policy.
